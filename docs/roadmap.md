# Roadmap

一纸成账 Paper2Ledger 的任务清单与后续计划。已完成部分保留任务编号，便于与
`docs/development-log.md` 里的开发日志对照。

## 已完成

### 阶段一 · 提取引擎（对标 invoice2data）

- [x] E1 提取流水线 `app/services/extractors/`：统一接口 + 级联调度（模板 → LLM → 规则），条目记录来源与置信度，轻量列迁移
- [x] E2 模板提取器：关键词命中 + 每字段多条正则，模板管理 API（增删改查、贴文本试提取）
- [x] E3 业务字典：分类 / 支付方式 / 账户，LLM 提取的分类选项从字典读取
- [x] E4 「模板与字典」管理页，单据详情显示提取来源标签

### 阶段二 · 数据模型与报表

- [x] E5 手工录入与修改留痕（谁 / 何时 / 原值→新值）
- [x] E6 报表中心：日结单、分类排行、环比对比、Excel 导出
- [x] E7 提取 schema 扩展：笔数、支付方式拆分，客单价与支付方式进报表

### 阶段三 · 界面

- [x] E8 看板：环比涨跌、饼图下钻联动折线、月度对比
- [x] E9 按角色区分默认首页
- [x] E10 移动端适配、单据搜索/分页/状态筛选、月度目标与进度

### 阶段四 · 稳定性与安全

- [x] E11 登录安全：连续 5 次密码错误锁定 10 分钟；首次登录强制改密
- [x] E12 数据备份：一键打包、30 天清理、下载与删除、路径穿越防护

### 阶段五 · 工厂台账改造（2026-09-02 立项）

业务定位从「通用经营分析」改为「中小型工厂（螺母等多规格产品）每日台账」。关键决策：
做库存结存但不建库存表（由流水实时聚合）、出货挂客户文本字段而不建客户主数据、
旧财务页面从菜单移除但数据保留、文档识别与三级提取链路全部保留并改造为条目式输出。

- [x] L1 底座：`products` / `ledger_entries` / `ledger_edits` 三表，产品管理与台账手工录入，库存结存计算
- [x] L2 提取改造：三提取器输出规格条目 + 产品三级匹配（精确 → 归一化 → 包含）+ 待确认队列
- [x] L3a 看板切生产主题：产量/出货双线、规格出货饼图下钻、库存结存表与告急提醒
- [x] L3b 台账报表：逐日 × 规格结存流转 + 规格汇总 + Excel 导出
- [x] L4 AI 助手切台账口径：8 个查询工具 + 三类异常预警（断产 / 出货骤降 / 库存告急）
- [x] L5 会话记忆：LangGraph `AsyncSqliteSaver` + 会话表 + 历史回放，多轮追问携带上下文
- [x] L6 可视化报告：指标卡 / 趋势 / 排行 / 库存四块由后端算，LLM 只写文字，支持打印存 PDF
- [x] L7 主备双模型兜底：主服务商超时/5xx/欠费自动切备用（提取与报告走 `smart_chat`，智能体走 `with_fallbacks`）
- [x] L8 定时自动备份：每日到点打包（含会话记忆库），错过补跑，设置页可开关
- [x] L9 公开仓库安全加固：JWT 密钥不留默认值、强制改密服务端拦截、上传判限不整份进内存、
  Excel 导出防公式注入、备份还原防 zip slip、备份改用 SQLite 备份 API 避免漏掉 WAL

## 后续计划

按"值得做"排序，前四项是已知边界，不是遗漏：

- [ ] PDF 条目提取的端到端实测（解析与上传链路完好，缺带真实 PDF 的验证）
- [ ] 提取质量评测集：按字段统计 precision / recall / F1，分模板 / 规则 / LLM 三档出报告，
      让"模板优先于 LLM"从设计主张变成可验证结论
- [ ] 结构化表格直取：CSV/XLSX 有表头时按列名映射取精确单元格值，不再压成文本用正则重建
- [ ] 上线部署：目前只在局域网单机运行；公网部署需要先补 TLS、IP 维度限流，并把 LLM Key 从明文存储改为加密或外置
- [ ] 大文件防护：xlsx/docx 是 zip 容器，尚未加解压膨胀上限；PDF 解析 CPU 密集，单进程下并发上传会排队
- [ ] 可选：CI 上跑冒烟与评测，把结果做成公开徽章
